# 主动触达目标用户

## 明确找谁

读取 `.project/project.json` 和 `.project/brief.md`，使用本轮选定推广线的产品、受众、触发场景、公开信号、排除信号和有效线索口径。主动索要缺失的产品或目标用户信息。画像仍是假设时，先用少量公开证据检验，交负责人确认后再进入发布。岗位、关注关系或单个词只能提供线索，结合当事人的实际公开表达判断场景。只保存支撑匹配所需的公开信息。

## 找到能接上的对话

- 组合用户会用的词、具体情境、问题和替代方案。按 `scout-showcases` 的「检索工具选择」和项目授权选平台与数据源。可以用已授权的 ScrapeCreators `comment-mining` 辅助取样。采集工具返回的是研究素材，发布使用项目实际授权的平台账号和工具。
- 找目标用户可能聚集的博主，抽查多条相关原帖和评论，记录具体讨论及其与画像的关系。按证据判断受众适配。可同时找可能符合画像的公开账号，定位其正在讨论相关问题的具体帖子。
- 候选必须有原帖链接，以及要回复的楼层、评论链接或可复核的位置。区分作者观点与评论者的实际需求。只引用能看到的对话，缺正文或前后楼时补看原帖，仍无法核实时留待核验。排除无关讨论、只有推广信号、近期已经触达过的重复机会。内容值得拆时可另交候选池，互动判断独立记录。

## 写一条读过现场的人会写的评论

读原帖正文、要回复的那句和相关前后楼。先判断这里的人怎么叫这个问题、用什么语气、哪些梗适用。小圈子的术语和梗以可见用例为准。意思或语境不确定就用直白的话。

围绕对方刚提到的一个具体细节写一条简短评论。能补办法就给一个可用办法。缺决定性的细节时，问一个对方容易回答的具体问题。钩子可以是一条检查方法、一份清单、一个例子或自然的追问。产品和链接只有在直接帮到当前讨论、符合账号身份与社区规则时才提。有品牌关联就如实表述。经历、身份、客户案例和效果数字都必须有来源。语境读不懂或没实质内容可补时，跳过。

发给负责人前检查三点：

1. 换成同领域另一条帖子，如果评论仍完全成立，就回去接住原帖具体细节。
2. 用词、句长和语气符合这段讨论。删掉空泛称赞、标准营销句式、硬塞的黑话和重复 CTA。
3. 评论本身能帮到讨论。即使没有产品链接，对方也有理由看完或回复。

例。原帖说「改完稿后客户把意见散在三个群里，我每次都漏一条」。可接「最容易漏的是『顺手再改一下』那种。你们现在是最后指定一个人收口，还是三个群里的意见都算数？」等对方回了，再按新上下文给办法。

## 交审与执行

交审每条附平台、原帖与目标楼层、公开匹配证据、拟用账号、精确草稿和可选钩子。只有负责人的明确批准覆盖目标、账号和当前草稿时才发布。查当前平台与该社区的规则，使用授权账号。范围不明确、帖子已变化或文本有实质修改时重新交审。没有可用发布工具时交付可复制草稿供负责人手动发布。禁止批量铺同文、假扮用户或跳过平台限制。

发前重新打开原帖，核对目标楼层、当前账号和已有回复。把状态记为「提交中」再执行。成功后读回公开回复并登记链接或可核验定位。结果不明时先查当前楼层和该账号实际发出记录，核实前保留「待回读」且不重复提交。对方有实质回复时重新读上下文，后续回复按同一审批规则处理。

## 回写与复盘

默认在项目私有 `.project/outreach.md` 维护记录。按平台、发布账号和稳定回复目标去重，同一对话的后续回复追加在原记录中。保存推广线、公开来源、证据、草稿、批准状态、实际发布定位和时间、后续反馈、是否达到有效线索口径。只记录公开定位和业务判断所需信息，保留人工决定。单独区分已发互动、实质回复、后续交流和有效线索。证据不够时标未知。

每轮留下一个要验证的变化及指标，记录下一轮应继续观察的博主、问题词或评论写法。把能支持或推翻画像的证据反馈到项目简报，负责人确认后再更新画像。同一条线索可能同时接触过内容和评论，能核实来源才归因。回传内容复盘时沿用同一线索口径并避免重复计数。
