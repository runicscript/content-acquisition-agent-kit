# 管理已选案例

从当前项目的配置及已验证的飞书资源映射读取身份和资源。只访问本项目创建并核验过的表和文档。飞书运行方式见 docs/feishu.md。本地模式在 `.project/data/cases/` 下按案例编号维护三个 Markdown 文件及一个案例索引。未授权写入时交付本地草稿和待同步说明。

- 案例。每条选中作品建一份案例文档和一条 Showcase 记录。先分页读表并核对平台作品 ID 或原链接，标题用来辅助查找。记录稳定编号、平台、形式、标题、作者、原作定位、入选理由和选择人。先存文档，再用文档链接登记案例行。
- 拆解。调用 showcase-breakdown。为该案例创建独立拆解文档，引用案例，逐页或逐段记录证据、可复用结构和成立条件。在同一行更新拆解链接。
- 内容方案。为该案例创建独立方案文档。在同一文档内追加明确编号的各版 Spec、SOP、变更原因、制作、发布和复盘记录。每条发布引用实际采用的版本。已确认的旧版正文、人工批注和旧版链接须保留。
- 有效评级。新案例默认待定。只有负责人或复盘环节给出明确版本、评级及依据时，才记录到对应版本并更新案例行。生产、追加草案、发布登记都不触发评级变化。有冲突则保留已有决定并交负责人确认。

复用 templates/ 中的案例、拆解和方案文档结构。三个链接指向该案例各自的实际文档。未生成文档的列留空。写已有行时用真实记录 ID，只更新本次核实的字段。失败重试先查文档和记录是否已创建，再决定是否补写。每次写后回读相应行及链接，保留人工字段。
