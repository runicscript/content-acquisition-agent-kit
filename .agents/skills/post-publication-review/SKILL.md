# 发布后复盘

**未完待续。** 本技能是复盘起点。用实际发布案例检验指标口径、观察窗口和归因规则，逐轮积累证据。

## 对齐作品与数据

通过 manage-showcases 读取案例行、有效评级和内容方案文档。从指定版本的发布记录核对平台、账号、作品链接或 ID、发布日期、版本、主推产品和推广线。一个版本可有多条作品；一条作品只计一次。旧版本沿用原归属。只有成片、草稿或对标账号数据时不能判定自己的方案效果。作品与版本关系不明时先列待确认项，不写评级。

优先使用负责人授权的后台数据、导出、截图或跟进记录；公开可见数据只用于其实际展示的指标。记录来源、数据截至时间、距发布多久、平台指标名和单位。缺失写未知；已核实无结果才写零。不要索取私人聊天原文来证明线索，汇总数或去标识化归因已足够。

## 平台数据口径

小红书从「数据看板 → 内容分析 → 笔记数据」的授权导出、截图或实屏读取曝光、观看、封面点击率、人均观看时长。按疑问选看收藏、评论、涨粉、分享；字段不适用或没有返回时注明。采用平台原始点击率。首页账号总览、主页访客以及同期间商品总销量均不能分摊到笔记。

其他平台以项目已确认、能定位到作品的后台口径为准。缺少口径时仅整理可见数据和证据，待核实后再按平台形成评级。跨平台分别报告指标与基准。

与同账号、同形式、相近发布时长的笔记比较，记录样本、基准、付费推广等差异。只有一篇且缺目标或参照时先描述表现。曝光、点击和停留分别诊断；点击偏低可测试封面或标题，停留偏低可测试正文是否兑现开头承诺。一次只提出一个优先验证项。已核实的主动咨询可按产品口径另列，来源未知不分配到某个版本。

## 业务结果与来源归因

按项目确认的推广线、产品与观察窗口核实对应结果。自助可以跳过咨询直接完成激活。上架销售线按具体商品核实可购买状态；未上架时成交记「不适用（未上架）」，不计算购买转化率，也不影响内容评级。上架时在实际方案版本记录产品、上架时间、推广作品链接与发布时间。跨上线或上架日期的窗口分开观察。

发生实际支付后，核对后台是否能把支付量归到可识别作品，分别记录按作品汇总、逐单可定位和仅有商品总量三个证据层级。只有商品总量时，作品成交记未知。日期相近、流量高或只看到一个推广帖都不足以完成归因。用汇总或脱敏证据，无需收集客户身份。

## 有效评级与下一步动作

评级针对实际使用的版本，主看流量复用价值，获客结论另列。优先采用该项目已确认的指标、阈值和观察窗口。没有明确阈值时报告相对表现与依据，不自行设百分比门槛。明显优于可信基准且足以支持优先复用可评高，与常态相当可评中，观察窗口充分且明显偏弱可评低。单条作品的判断标明单条样本，不将相关性写成因果；样本矛盾、基准不足或窗口未满则版本结论为待定，已有表评级不因缺数据而下调。无发布数据的新案例维持待定。

每次给出一项可执行决定：复用确切版本、继续观察到指定窗口，或提出一项改动和下轮验证指标。流量高但有效线索少，先检查受众、承诺和行动入口；线索合格但调用失败，检查接入环节。诊断写成待验证解释。改版由负责人拍板；分析不覆盖 Spec，不自动生产或发布。

## 交付与登记

先用一段话回答“哪个版本值得用、依据是什么、下一步做什么”，附作品、时间窗口、主指标与基准、可归因线索、后续结果和缺口。再调用 manage-showcases，在实际版本下追加复盘，保留数据来源与评级理由；按作品／版本／观察截止时间去重，纠错注明依据。若仅要求预览则只交付分析。
一行可能有多个版本。行内评级对应当前有证据、应优先复用的版本，在内容方案文档中明确其产品、版本、评级和最近复核日期。另一版本产生新数据时先比较当前引用版本；新版本表现低或待定，不覆盖仍有效的高评级版本。不可比时保留原评级并分别说明。已有人工结论遇到冲突时列明并请负责人裁决。先存版本证据再交管理 skill 回写及回读，不加表、不增列。

## 下轮迭代

在本次复盘下追加一条待续记录，写明待验证假设、下一轮唯一优先改动或补数动作、对照版本、验证指标、观察截止时间与负责人。下次先回读上轮待续记录，补记验证结果和采用决定。证据不足时继续标记待验证。

遇到重复出现的指标、归因或回写缺口，把脱敏案例、证据和建议改法记入项目迭代清单。负责人确认后再更新 Skill 规则和模板，保留适用条件与改动依据。
