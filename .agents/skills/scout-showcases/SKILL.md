# 获客账号与内容检索

交付一个能让负责人快速决定「拆账号 / 拆这条内容 / 观察 / 略过」的候选池。到人工选择为止。检索频率由调用者设置。

## 输入与范围

读取指定产品说明，提取产品、买方、问题、获客动作和有效线索定义。区分原文事实与暂定假设。至少需要可识别的产品、受众或用途，以及允许检索的平台。缺少平台或产品无法辨识时请求补充；无人值守则报告缺项。时间窗、地域、语言、候选上限、既有候选库均可指定。只把公开检索词提交给搜索服务，勿传整份内部文档。只在指定平台纳入候选。

## 按推广线确定检索口径

以「推广对象＋目标人群＋采用方式」划分推广线。先从项目说明或负责人已确认的记录中读取每条线的四项口径：谁在什么场景会采用；哪个可跟进的主动行为算有效线索；哪个可核实的后续动作算激活或商业结果；检索对标时优先看哪些公开证据。以实际采用方式区分自助和对接交付，不能仅凭 Skill、MCP 等技术名称推定。多个推广线分别筛选、排序；同一作品可在不同线有不同推荐理由。

负责人已确认的口径按项目复用。首次缺少口径时给出基于文档的提案；可以做探索检索，但正式排序前要确认。无人值守时保留待确认样本。推广对象、人群或采用方式变化时才重新确认。公开询问、作者的体验入口、实际采用与付费分别记录。自助用户可以跳过咨询直接激活。按推广线和阶段去重，不将阶段人数相加为获客人数。

## 如何发现

两条研究线独立开展，按结果调整查询，不强行凑齐数目。
- 同类产品线：用买方自己的问题措辞、竞品/服务类别、行业角色分别组合场景或决策词。例如外贸询盘服务可搜索「外贸业务员 漏回询盘」「外贸团队 询盘管理 演示」。既搜品类名，也搜不知道产品名的人会说的话。
- 可迁移机制线：从其他品类找受众相近、决策过程相似或承接动作可借鉴的案例。企业 AI 服务可以搜「企业 AI 工作流 客户案例」或「AI 自动化 预约演示」。说明借鉴哪种方法及成立条件。
- 作品和账号是两类独立候选。关键词找到单条作品后可回查作者主页；从账号发现作品时挑出具体原作。优先比较近期热门、近期普通作品和明确面向买方的案例。单条作品成立即可推荐；升级为账号候选须有主页和多条相关作品支撑。必要时热点辅助拓词，再回指定平台核实作品。
- 记录实际查过的平台、查询词、日期窗口、排序和取样限制。已有候选池时优先寻找新增、核实有变化的旧条目。边际结果开始重复或达到给定预算即可停止。

## 检索工具选择

按仓库的 docs/dependencies.md 选择当前环境已获授权的辅助能力，先读取其说明，按当前环境验证搜索、原作定位和可读指标。仅调用检索需要的只读功能；认证失败、计费条件不明或没有可用入口时换已授权路径，仍失败就说明缺口。
- 小红书优先用「小红书关键词搜索、笔记详情获取、评论内容获取分析、博主作品监控助手」搜笔记、回查博主。「小红书作品爬取」可按时间排序补漏。前者需要 GUAIKEI_API_TOKEN，后者有独立鉴权。
- 抖音优先用「抖音内容洞察」关键词搜视频、用户，查作者作品和必要评论；需要 GUAIKEI_API_TOKEN。「抖音搜索分析」功能重合，同一查询无需重复跑。「抖音热榜」仅作拓词。
- 视频号从可访问的原生搜索找账号或视频，保存可复核分享入口；若只有用户给的素材，标为人工提供而非主动发现。已知账号的付费快拆及本地视频拆解留给下游；公众号文章不能当作视频号作品。
- Threads 在可用的站内搜索中分别找帖子与作者，以买方语言搜问题、产品类别或同行，回查原帖及回复。站内入口不可用时可用公开网页索引定位，再查原帖，标注检索范围有限。浏览器工具、热点工具均为可选。不得将未能访问解释为没有候选。

## 如何筛选

先检查平台、对象身份、可重开的原作或主页入口。无法核验的线索单列「待核验」，不进推荐。针对每条分别评价：
- 买方或机制相关：具体服务谁、解决什么问题，或者为什么它的获客做法在本产品也成立。说不出任何一点则淘汰。
- 流量证据：记录指标名、原始值、观察日、发布时间。优先与同平台同形式同时段作品或该作者近期作品比。写明样本和基准；无法比较就只报数值。隐藏的数据写未知，不能把赞当播放、跨平台按绝对数排序。
- 获客证据：分开写卖方动作（如预约入口）、买方反应（如询价/求演示）和可核实的成交数据。主页有联系方式不等于有咨询，评论不等于订单。看不到订单时写未知。
- 值得拆什么：用一句话指出可迁移的表现方式、信任证据或承接动作。内容只做初筛，无须还原脚本。
- 相关性明确、可借鉴点具体且有相对高表现或买方反应，优先推荐；仅有热度且受众偏离则略过。相关但证据少的放观察。避免同一作者多个近似案例挤占清单。

## 呈现与保存

按账号、单条内容分组。每条展示编号、平台、可点击原链接/分享定位、作者与标题、对标类型、可见表现与基准、获客证据、推荐拆什么。账号附代表作链接。默认展示最值得看的各至多 3 条，可按请求调整。末尾列覆盖缺口和新增/更新数，让负责人按编号选择。没有合格项就交空清单并说明查过哪里。

使用本项目新飞书的候选池表，按 docs/feishu.md 读取本地资源映射，显式指定项目身份，写前查询，写后回读。记录所属产品、推广线 ID、平台、对象类型、平台对象 ID 或稳定定位、原分享链接、发现与最近核验时间、上述证据和人工决定。以产品＋推广线 ID＋平台＋对象类型＋平台 ID 去重。无平台 ID 时用可核实的稳定定位。分享所需参数保留在原链接中。重复运行更新证据，保留人工状态和备注。人工未决定的一律为「待挑选」；自动排序不等于人工选择。已略过的对象仅在出现新的实质证据时单独提示。

未指定飞书表或写入失败时，在项目的 .project/data/candidates.md 维护同字段候选记录，保留稳定编号和人工决定，报告实际路径及待同步状态。禁止使用 CSV 格式落表。无持久化权限则在对话交付并说明未保存。产品说明留在文档，候选逐条存储。仅汇报实际成功的检索与保存。
